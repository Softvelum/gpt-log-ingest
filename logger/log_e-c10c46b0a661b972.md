# DVR export audio timescale changed

Product: Nimble Streamer
Component: DVR export
Logging function: log_e
Log level: error
Documentation ID: log_e-c10c46b0a661b972

## Log pattern

```text
audio timescale changed period=%d stream=%s utc_start=%lld utc_end=%lld
```

## Parameters

- Argument 1 — Recording period: Integer identifier of the continuous recording period.
- Argument 2 — Stream: Text naming the application and stream.
- Argument 3 — UTC start: 64-bit requested UTC start in seconds since the Unix epoch; zero leaves this bound unspecified.
- Argument 4 — UTC end: 64-bit requested UTC end in seconds since the Unix epoch; zero leaves this bound unspecified.

## Log examples

Illustrative examples; these are not captured server logs.

```text
audio timescale changed period=1 stream=live/camera utc_start=1700000000 utc_end=1700000060
```

## Short description

DVR export audio timescale changed.

## Trigger condition

An audio fragment has a different timescale from earlier fragments during audio-only preparation.

## Explanation

Parsing fails and the export closes.

## Possible causes

- An audio fragment has a different timescale from earlier fragments during audio-only preparation.

## What to check

1. Export a range with a consistent audio timescale or correct recording timestamp configuration.

## Recommended action

Export a range with a consistent audio timescale or correct recording timestamp configuration.
