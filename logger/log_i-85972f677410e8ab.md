# DVR audio period resets after UTC alignment changes

Product: Nimble Streamer
Component: DVR recording
Logging function: log_i
Log level: info
Documentation ID: log_i-85972f677410e8ab

## Log pattern

```text
reset period=%u on program date time reset stream='%s' a_segment time=%llu start_time=%llu proto_start_time=%llu
```

## Parameters

- Argument 1 — Recording period: Unsigned identifier of the current recording period.
- Argument 2 — Stream: Text naming the application and stream.
- Argument 3 — UTC time: Unsigned segment UTC time in milliseconds since the Unix epoch.
- Argument 4 — Segment start: Unsigned media timestamp in the track timescale.
- Argument 5 — Protocol start: Unsigned incoming presentation timestamp in the track timescale.

## Log examples

Illustrative examples; these are not captured server logs.

```text
reset period=1 on program date time reset stream='live/camera' a_segment time=1700000000000 start_time=90000 proto_start_time=180000
```

## Short description

DVR audio period resets after UTC alignment changes.

## Trigger condition

UTC alignment mode changes, or aligned presentation time fails to progress consistently within five seconds of the current UTC clock.

## Explanation

The already-saved segment ends the current period; the caller is asked to reset before further recording.

## Possible causes

- UTC alignment mode changes, or aligned presentation time fails to progress consistently within five seconds of the current UTC clock.

## What to check

1. Check input presentation timestamps, server-clock changes, and program-date-time alignment settings.

## Recommended action

Check input presentation timestamps, server-clock changes, and program-date-time alignment settings.
