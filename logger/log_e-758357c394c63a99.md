# SLDP playback falls behind the retained buffer

Product: Nimble Streamer
Component: SLDP playback and advertising
Logging function: log_e
Log level: error
Documentation ID: log_e-758357c394c63a99

## Log pattern

```text
client s=%d ip='%s' stream='%s/%s' is too slow [1]
```

## Parameters

- Argument 1 — Socket: Connection descriptor reported by the playback transport.
- Argument 2 — Client IP: Connected playback client address.
- Argument 3 — Application: Effective application name after alias mapping when present.
- Argument 4 — Stream: Playback URL stream name.

## Log examples

Illustrative examples; these are not captured server logs.

```text
client s=42 ip='192.0.2.30' stream='live/camera' is too slow [1]
```

## Short description

SLDP playback falls behind the retained buffer.

## Trigger condition

The next required media item has already left the retained buffer without advertising.

## Explanation

The output operation fails and the caller closes the playback connection. The numbered suffix identifies this playback phase.

## Possible causes

- The next required media item has already left the retained buffer without advertising.

## What to check

1. Check client receive speed, network capacity, and source media rate.

## Recommended action

Restore sufficient receive throughput before restarting playback.
