# Overlay timestamp resynchronized

Product: Nimble Streamer
Component: Video filtering
Logging function: log_i
Log level: info
Documentation ID: log_i-50e09cb0366622be

## Log pattern

```text
resynced overlay stream=%s with main_stream=%s pts=%lld(ms) => sync_pts=%lld(ms), filter=%s
```

## Parameters

- Argument 1 — Input: Input stream name, text.
- Argument 2 — Main input: Main video stream name, text.
- Argument 3 — Original timestamp: Original overlay presentation timestamp, signed 64-bit ticks in that frame time base; the literal ms label is only correct for a 1/1000 time base.
- Argument 4 — Adjusted timestamp: Main presentation timestamp converted to the overlay frame time base, signed 64-bit ticks; the literal ms label is not a conversion.
- Argument 5 — Filter: Configured filter identifier, text.

The log prints raw timestamp values. They are milliseconds only when the overlay frame time base is 1/1000. The timestamps are signed 64-bit values passed to signed long-long conversions without casts. These types differ on platforms where the 64-bit typedef is signed long.

## Log examples

The timestamps are signed 64-bit values passed to signed long-long conversions without casts. These types differ on platforms where the 64-bit typedef is signed long. A reliable example is omitted because the original call does not ensure matching printf argument types.

## Short description

Overlay timestamp resynchronized.

## Trigger condition

An eligible overlay resumes after end-of-input or differs from the main timeline by more than five seconds, and the main timestamp has advanced since its previous synchronization.

## Explanation

The overlay offset is changed to align this frame to the main timestamp; a cloned frame receives the adjusted timestamp when needed.
