# RTMP advertising requests the next schedule interval

Product: Nimble Streamer
Component: RTMP output and advertising
Logging function: log_d
Log level: debug
Documentation ID: log_d-6b8f900f9330a7fc

## Log pattern

```text
s=%d, request contents %lld %lld
```

## Parameters

- Argument 1 — Socket: Operating-system socket descriptor for the affected connection.
- Argument 2 — Interval start: Previously requested stream-time boundary in whole seconds.
- Argument 3 — Interval end: Current stream time rounded down to seconds plus six seconds.

## Log examples

Illustrative examples; these are not captured server logs.

```text
s=42, request contents 60 66
```

## Short description

RTMP advertising requests the next schedule interval.

## Trigger condition

The current playback stream time reaches the end of the previously requested advertising interval.

## Explanation

Advertising rules are queried through six seconds beyond the current stream time, and the scheduling cursor advances to that end. This does not confirm that an advertisement was selected.

## Possible causes

- The current playback stream time reaches the end of the previously requested advertising interval.

## What to check

1. Check the interval boundaries and configured advertisement schedule.

## Recommended action

No action is required for expected schedule polling.
