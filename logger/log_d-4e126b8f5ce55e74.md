# SLDP remembers a newly due advertising item

Product: Nimble Streamer
Component: SLDP playback and advertising
Logging function: log_d
Log level: debug
Documentation ID: log_d-4e126b8f5ce55e74

## Log pattern

```text
s=%d, video_sn=%d, audio_sn=%d added last ad content, start_time=%lld %s
```

## Parameters

- Argument 1 — Socket: Connection descriptor reported by the playback transport.
- Argument 2 — Video number: Client-assigned video stream number for this playback selection, or its default value when no video is selected.
- Argument 3 — Audio number: Client-assigned audio stream number for this playback selection, or its default value when no audio is selected.
- Argument 4 — Shared start: Current stream time recorded for the shared item, in milliseconds.
- Argument 5 — Content URI: Configured URI of the advertising media item.

## Log examples

Illustrative examples; these are not captured server logs.

```text
s=42, video_sn=1, audio_sn=2 added last ad content, start_time=60000 https://media.example/ad.mp4
```

## Short description

SLDP remembers a newly due advertising item.

## Trigger condition

The first pending advertising item is due and is selected as the common last content.

## Explanation

The shared start is set to the current stream time, allowing other media selections to join the same content. The item is removed from the pending schedule.

## Possible causes

- The first pending advertising item is due and is selected as the common last content.

## What to check

1. Check the shared content URI and selection timing.

## Recommended action

No action is required for expected insertion.
