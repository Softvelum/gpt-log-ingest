# Stream-check response failed HTTP parsing

Product: Nimble Streamer
Component: Linux stream availability checks
Logging function: log_v
Log level: verbose
Documentation ID: log_v-3d4e7ef39d2b6670

## Log pattern

```text
bad response from origin s %d:
%.*s
```

## Parameters

- Argument 1 — socket: Socket descriptor for the stream-check connection.
- Argument 2 — length: Maximum number of response characters printed.
- Argument 3 — response: Accumulated response bytes shown up to the supplied length.

## Log examples

Illustrative examples; these are not captured server logs.

```text
bad response from origin s 12:
invalid response
```

## Short description

Stream-check response failed HTTP parsing.

## Trigger condition

The HTTP-style parser rejects accumulated HTTP or RTSP response bytes.

## Explanation

A recognized Icecast success prefix is still treated as an available stream; other rejected input records a parse failure. The task then shuts down.

## Possible causes

- The origin response is invalid for this parser or uses the separately recognized Icecast status format.

## What to check

1. Inspect the shown response and intended origin protocol.

## Recommended action

Correct the origin response or monitored URL if it does not match the expected stream protocol.
