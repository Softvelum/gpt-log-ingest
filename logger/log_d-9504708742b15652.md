# RTMP audio and video advertising timing is established

Product: Nimble Streamer
Component: RTMP output and advertising
Logging function: log_d
Log level: debug
Documentation ID: log_d-9504708742b15652

## Log pattern

```text
s=%d, %s content start, start_time=%lld, initial_video_timestamp=%lld, initial_audio_timestamp=%lld
```

## Parameters

- Argument 1 — Socket: Operating-system socket descriptor for the affected connection.
- Argument 2 — Content URI: Configured URI of the selected advertising media item.
- Argument 3 — Start time: Advertisement start in the playback stream timeline, in milliseconds.
- Argument 4 — Initial video timestamp: Video timestamp assigned to the content start, rescaled to milliseconds.
- Argument 5 — Initial audio timestamp: Audio timestamp assigned to the content start, rescaled to milliseconds.

## Log examples

Illustrative examples; these are not captured server logs.

```text
s=42, https://media.example/ad.mp4 content start, start_time=60000, initial_video_timestamp=120000, initial_audio_timestamp=120000
```

## Short description

RTMP audio and video advertising timing is established.

## Trigger condition

A loaded audio/video advertising reader has been aligned with the current stream insertion point.

## Explanation

The reader starting timestamps are set while preserving its initial audio/video offset; metadata and sequence headers are sent next.

## Possible causes

- A loaded audio/video advertising reader has been aligned with the current stream insertion point.

## What to check

1. Compare the initial audio/video timestamps and stream-relative start with the desired insertion timing.

## Recommended action

No action is required for an expected advertisement start.
