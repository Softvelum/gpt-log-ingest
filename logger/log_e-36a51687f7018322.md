# RTMP legacy audio codec changes midstream

Product: Nimble Streamer
Component: RTMP media input
Logging function: log_e
Log level: error
Documentation ID: log_e-36a51687f7018322

## Log pattern

```text
[AM] sound format changed %d->%d
```

## Parameters

- Argument 1 — Previous audio format: Previously established numeric RTMP audio format.
- Argument 2 — New audio format: Numeric RTMP audio format in the received message.

## Log examples

Illustrative examples; these are not captured server logs.

```text
[AM] sound format changed 10->2
```

## Short description

RTMP legacy audio codec changes midstream.

## Trigger condition

A supported legacy audio format differs from the format already established for the message stream.

## Explanation

The changed audio message is rejected and connection processing fails.

## Possible causes

- A supported legacy audio format differs from the format already established for the message stream.

## What to check

1. Compare the initial and new audio codec settings at the encoder.

## Recommended action

Keep the audio format consistent during the connection or start a new publication for the changed format.
