# Verbose access diagnostic or SMIL input list

Product: Nimble Streamer
Component: HTTP client sessions
Logging function: log_v
Log level: verbose
Documentation ID: log_v-4956868ab3aa7182

## Log pattern

```text
%s
```

## Parameters

- Argument 1 — Diagnostic text: Complete dynamically constructed access-check message, or a multiline list containing the request path and each required SMIL file, path, track indexes and bitrates.

## Log examples

Illustrative examples; these are not captured server logs.

```text
user [192.0.2.10] is in deny list
```

## Short description

Verbose access diagnostic or SMIL input list.

## Trigger condition

An access-check failure is forwarded at the selected verbose level, or a remote SMIL request lists the VOD inputs it needs while verbose logging is enabled.

## Explanation

Access text can describe IP, geography, agent or referrer denial; connection/bandwidth limits; or signature, client-ID, clock, expiry, and hash failures. Most such checks return a failure or timeout, while early malformed-signature diagnostics continue validation. A SMIL list is normal progress before checking and fetching required media. Optional access-log storage is independent of this verbose output.

## Possible causes

- An access-check failure is forwarded at the selected verbose level, or a remote SMIL request lists the VOD inputs it needs while verbose logging is enabled.

## What to check

1. Use the actual text to distinguish an intended access restriction from signature or clock problems; SMIL input lists need no action unless a later required-media fetch fails.

## Recommended action
