# Audio transport buffer cannot grow

Product: Nimble Streamer
Component: Live media packaging and timed metadata
Logging function: log_e
Log level: error
Documentation ID: log_e-6413dc14a8639621

## Log pattern

```text
[AM] cannot allocate buffer message body for [%s/%s], used_size=%u, frame_size=%u, ts=%llu
```

## Parameters

- Argument 1 — Application: Application containing the live stream.
- Argument 2 — Stream: Live stream name.
- Argument 3 — Used size: Bytes already used in the affected output buffer.
- Argument 4 — Frame size: Media payload size in bytes, including any prepared transport header.
- Argument 5 — Timestamp: Audio timestamp in 90 kHz ticks.

## Log examples

Illustrative examples; these are not captured server logs.

```text
[AM] cannot allocate buffer message body for [live/camera], used_size=1048576, frame_size=4096, ts=90000
```

## Short description

Audio transport buffer cannot grow.

## Trigger condition

HLS or MPEG-TS over HTTP cannot reserve the used bytes plus twice the audio payload and two 188-byte transport packets.

## Explanation

Audio transport packaging returns failure. Opus uses the MPEG-TS output path and bypasses this HLS path.

## Possible causes

- HLS or MPEG-TS over HTTP cannot reserve the used bytes plus twice the audio payload and two 188-byte transport packets.

## What to check

1. Check accumulated output size, audio group size, and allocation limits.

## Recommended action

Resolve oversized audio groups or insufficient output-buffer capacity.
