# Windows exception register state recorded

Product: Nimble Streamer
Component: Process signals and exception diagnostics
Logging function: log_e
Log level: error
Documentation ID: log_e-3727f18405c284af

## Log pattern

```text
Load Addr: %#x StIIP: %#x IntSp: %#x RsBSP: %#x
```

## Parameters

- Argument 1 — Module base: Executable module base address printed in hexadecimal.
- Argument 2 — Instruction address: Captured instruction address printed in hexadecimal.
- Argument 3 — Integer stack pointer: Captured integer stack pointer printed in hexadecimal.
- Argument 4 — Register backing-store pointer: Captured register backing-store pointer printed in hexadecimal.

The format uses ordinary hexadecimal integer conversions for addresses. Pointer or 64-bit register values may be truncated; the text cannot guarantee full-width addresses.

## Log examples

Illustrative examples; these are not captured server logs.

```text
Load Addr: 0x400000 StIIP: 0x12340000 IntSp: 0x12340010 RsBSP: 0x12340020
```

## Short description

Windows exception register state recorded.

## Trigger condition

The unhandled-exception handler runs in a Itanium build.

## Explanation

The module load address and captured register values precede stack-trace reporting. Normal Windows exception handling continues afterward.

## Possible causes

- An unhandled Windows exception caused diagnostic reporting.

## What to check

1. Correlate these addresses with the preceding exception and following stack trace.

## Recommended action

Use the diagnostic state to investigate the exception.
