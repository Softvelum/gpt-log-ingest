# RTMP video-only advertising timing is established

Product: Nimble Streamer
Component: RTMP output and advertising
Logging function: log_d
Log level: debug
Documentation ID: log_d-5674c502b657cc19

## Log pattern

```text
s=%d, %s content start, video only, start_time=%lld, initial_video_timestamp=%lld
```

## Parameters

- Argument 1 — Socket: Operating-system socket descriptor for the affected connection.
- Argument 2 — Content URI: Configured URI of the selected advertising media item.
- Argument 3 — Start time: Advertisement start in the playback stream timeline, in milliseconds.
- Argument 4 — Initial video timestamp: Content starting timestamp rescaled to milliseconds.

## Log examples

Illustrative examples; these are not captured server logs.

```text
s=42, https://media.example/ad.mp4 content start, video only, start_time=60000, initial_video_timestamp=120000
```

## Short description

RTMP video-only advertising timing is established.

## Trigger condition

A loaded video-only advertising reader is assigned the stream insertion timestamp.

## Explanation

The content start is recorded on the playback stream timeline; metadata and any sequence headers are sent next.

## Possible causes

- A loaded video-only advertising reader is assigned the stream insertion timestamp.

## What to check

1. Check the video timestamp against the intended insertion point.

## Recommended action

No action is required for expected advertising playback.
