# SLDP advertising requests the next scheduling interval

Product: Nimble Streamer
Component: SLDP playback and advertising
Logging function: log_d
Log level: debug
Documentation ID: log_d-7733165972dca70b

## Log pattern

```text
s=%d, video_sn=%d, audio_sn=%d request contents %lld %lld
```

## Parameters

- Argument 1 — Socket: Connection descriptor reported by the playback transport.
- Argument 2 — Video number: Client-assigned video stream number for this playback selection, or its default value when no video is selected.
- Argument 3 — Audio number: Client-assigned audio stream number for this playback selection, or its default value when no audio is selected.
- Argument 4 — Interval start: Previous scheduling cursor in stream-time seconds.
- Argument 5 — Interval end: Current whole-second stream time plus six seconds.

## Log examples

Illustrative examples; these are not captured server logs.

```text
s=42, video_sn=1, audio_sn=2 request contents 60 66
```

## Short description

SLDP advertising requests the next scheduling interval.

## Trigger condition

The playback stream time reaches the end of the previously requested advertising interval.

## Explanation

Rules and content are requested through six seconds beyond current whole-second stream time. Rule retrieval can complete asynchronously before content selection.

## Possible causes

- The playback stream time reaches the end of the previously requested advertising interval.

## What to check

1. Check interval boundaries and rule-query completion.

## Recommended action

No action is required for expected schedule polling.
