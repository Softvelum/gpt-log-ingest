# Cached body update can resume sending

Product: Nimble Streamer
Component: HTTP client sessions
Logging function: log_d
Log level: debug
Documentation ID: log_d-81203d0e27d6cd59

## Log pattern

```text
[CliS::OnCIU] sst=%d ist=%d sz=%llu
```

## Parameters

- Argument 1 — Session state: Integer identifying the HTTP client session phase: 0 reading a request, 1 sending a response, 2 connecting to origin, 3 sending to origin, 4 reading origin headers, 5 reading an origin playlist, 6 reading origin media, 29 shutting down, or 30 finished; intermediate values identify pending asynchronous work.
- Argument 2 — Cache state: Integer cache state: 0 newly reserved, 1 receiving data, 2 fragmented, 3 ready, or 4 marked for removal.
- Argument 3 — Stored bytes: Unsigned 64-bit amount of cached data in bytes.

## Log examples

Illustrative examples; these are not captured server logs.

```text
[CliS::OnCIU] sst=4 ist=1 sz=32768
```

## Short description

Cached body update can resume sending.

## Trigger condition

A body-waiting session observes a cache item that is receiving data or ready.

## Explanation

The available byte count is refreshed; output monitoring is enabled when new bytes arrive.

## Possible causes

- A body-waiting session observes a cache item that is receiving data or ready.
