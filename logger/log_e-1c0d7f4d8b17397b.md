# Active playlist block changed without a new identifier

Product: Nimble Streamer
Component: Server playlists
Logging function: log_e
Log level: error
Documentation ID: log_e-1c0d7f4d8b17397b

## Log pattern

```text
[ServerPlaylistProcessor] hash changed('%s'->'%s') for block=[%s],stream=[%s]
```

## Parameters

- Argument 1 — Previous signature: Text describing the old block settings.
- Argument 2 — New signature: Text describing the new block settings.
- Argument 3 — Block ID: Text identifying the schedule block.
- Argument 4 — Playlist stream: Text naming the output application and stream.

## Log examples

Illustrative examples; these are not captured server logs.

```text
[ServerPlaylistProcessor] hash changed('morning#old'->'morning#new') for block=[morning],stream=[live/channel]
```

## Short description

Active playlist block changed without a new identifier.

## Trigger condition

The selected block retains the active block identifier but has a different content signature.

## Explanation

The processor marks the playlist failed and requests that its worker stop.

## Possible causes

- The selected block retains the active block identifier but has a different content signature.

## What to check

1. Give changed active blocks a new identifier or restore the previous block definition.

## Recommended action

Give changed active blocks a new identifier or restore the previous block definition.
