```text

```

- Argument 1 — Scenario: Transcoding scenario identifier, text.

Illustrative examples; these are not captured server logs.

```text

```

## Short description

Scenario stopped after output inactivity.

## Trigger condition

An enabled inactivity check reaches three checks without received output frames or a settings reset; checks run about five seconds apart. Checks are skipped when only local device outputs are present, and the count resets when input senders exist but supplied no new frames in the previous interval.

## Explanation

The controller and connection mapping are removed, its child and outputs are cleaned up, and synchronization is invalidated to recreate a still-required scenario.

## Possible causes

- The scenario receives input activity or has no input sender, but produces no output for the inactivity check period.

## What to check

1. Check child diagnostics and whether input frames are reaching a scenario that should produce output.

## Recommended action

Correct stalled scenario processing or invalid input/output settings.
