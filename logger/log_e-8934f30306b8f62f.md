# RTMP control message uses the wrong chunk stream

Product: Nimble Streamer
Component: RTMP command handling
Logging function: log_e
Log level: error
Documentation ID: log_e-8934f30306b8f62f

## Log pattern

```text
Encoder violates the standard and sends cs_id=%d msg_id=%d for RTMP_CHUNK_WINDOW_ACK_SIZE_TYPE. Add 'rtmp_check_chunk_id_for_protocol_control_messages = false' to nimble.conf to FIX the issue
```

## Parameters

- Argument 1 — Chunk stream ID: Numeric RTMP chunk stream identifier carrying the control message.
- Argument 2 — Message stream ID: Numeric RTMP message stream identifier carried by the received message.

## Log examples

Illustrative examples; these are not captured server logs.

```text
Encoder violates the standard and sends cs_id=3 msg_id=0 for RTMP_CHUNK_WINDOW_ACK_SIZE_TYPE. Add 'rtmp_check_chunk_id_for_protocol_control_messages = false' to nimble.conf to FIX the issue
```

## Short description

RTMP control message uses the wrong chunk stream.

## Trigger condition

A window-acknowledgement-size message arrives on a chunk stream other than control chunk stream 2 while chunk-stream-ID checking is enabled.

## Explanation

The message is ignored and processing continues without applying that control update.

## Possible causes

- A window-acknowledgement-size message arrives on a chunk stream other than control chunk stream 2 while chunk-stream-ID checking is enabled.

## What to check

1. Check the encoder chunk stream IDs and the chunk-stream-ID validation setting.

## Recommended action

Configure the encoder to send control messages on chunk stream 2. The compatibility setting named in the message disables this check.
