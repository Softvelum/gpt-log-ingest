# DASH presentation timestamp precedes its offset

Product: Nimble Streamer
Component: Live stream codec and packaging setup
Logging function: log_i
Log level: info
Documentation ID: log_i-eaa47b63d9212f36

## Log pattern

```text
%s check dash availability time reset for [%s/%s]
```

## Parameters

- Argument 1 — Media: video or audio track triggering the reset.
- Argument 2 — Application: Application containing the affected live stream.
- Argument 3 — Stream: Live stream name.

## Log examples

Illustrative examples; these are not captured server logs.

```text
audio check dash availability time reset for [live/camera]
```

## Short description

DASH presentation timestamp precedes its offset.

## Trigger condition

The current presentation timestamp is below the established presentation-time offset for that track.

## Explanation

The DASH segment list is reset, the current track timestamp is reinitialized, and availability/publish times become unset until a later segment. Enabled presentation-time offsets are also updated.

## Possible causes

- The current presentation timestamp is below the established presentation-time offset for that track.

## What to check

1. Check the presentation timestamp and the earlier DASH offset after a source restart.

## Recommended action

Investigate unexpected backward timestamp jumps.
