# WHIP video codec changed mid-session

Product: Nimble Streamer
Component: WHIP publishing helper
Logging function: log_e
Log level: error
Documentation ID: log_e-4965f8428c83def5

## Log pattern

```text
video codec changed for whip session=%s/%s
```

## Parameters

- Argument 1 — Application: Application name, text.
- Argument 2 — Stream: Stream name, text.

## Log examples

Illustrative examples; these are not captured server logs.

```text
video codec changed for whip session=live/camera
```

## Short description

WHIP video codec changed mid-session.

## Trigger condition

A non-Opus media message names a video codec different from the nonempty codec already recorded for the WHIP session.

## Explanation

Frame processing fails; the caller closes the media socket and removes the active publication. Opus audio messages bypass this video-codec comparison.

## Possible causes

- The helper changes the video codec within one established publication.

## What to check

1. Check codec negotiation and whether the publisher switches video encoders without starting a new session.

## Recommended action

Start a new WHIP session for a codec change.
