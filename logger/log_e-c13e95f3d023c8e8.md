# File decoding resumed after a long interval

Product: Nimble Streamer
Component: Audio decoding
Logging function: log_e
Log level: error
Documentation ID: log_e-c13e95f3d023c8e8

## Log pattern

```text
decode interval gap detected, decode_interval=%lld for [%s]
```

## Parameters

- Argument 1 — Decode interval: Elapsed monotonic time since the previous decode iteration, unsigned 64-bit milliseconds printed in decimal.
- Argument 2 — Stream: Input stream name, text.

Shared by file-based audio and video decoding; both set the reader duration to elapsed time since decoding began. The elapsed interval is an unsigned 64-bit value, while the format requests a signed long-long value. Its exact compatibility depends on the platform integer typedef and value range.

## Short description

File decoding resumed after a long interval.

## Trigger condition

The time since the previous file-decoding iteration exceeds the configured maximum decode interval, converted from seconds to milliseconds.

## Explanation

The reader timeline is advanced to elapsed running time and decoding continues; this is not itself a fatal decode error.

## Possible causes

- The audio or video decoder loop was delayed beyond the configured interval.

## What to check

1. Check processing stalls or system load around the reported interval and the maximum-decode-interval setting.

## Recommended action

Resolve sustained processing delays; the worker already adjusts its timeline for this gap.
