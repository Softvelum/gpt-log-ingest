# Fragmented MP4 track reports a backward protocol timestamp

Product: Nimble Streamer
Component: HLS and DASH packaging
Logging function: log_v
Log level: verbose
Documentation ID: log_v-5ed12b0b551e36a9

## Log pattern

```text
%s_%s_fmp4::reset(%s, %llu, %llu)
```

## Parameters

- Argument 1 — Output kind: Packaging consumer label: dash, hls, or dvr.
- Argument 2 — Media: video or audio.
- Argument 3 — Stream: Stream label supplied to the segment builder.
- Argument 4 — Protocol time: New backward input timestamp in this track timescale.
- Argument 5 — Accumulated time: Current continuous track timestamp in this track timescale.

## Log examples

Illustrative examples; these are not captured server logs.

```text
dash_video_fmp4::reset(live/camera, 1000, 900000)
```

## Short description

Fragmented MP4 track reports a backward protocol timestamp.

## Trigger condition

Protocol-time reset is disabled, a new input timestamp is earlier than the prior segment protocol start, and no associated-track rewind information is pending.

## Explanation

The track notifies its associated track of the rewind while retaining its own accumulated time. The next segment begins after its sample state is reset.

## Possible causes

- Protocol-time reset is disabled, a new input timestamp is earlier than the prior segment protocol start, and no associated-track rewind information is pending.

## What to check

1. Check source timestamp continuity and the companion audio or video track.

## Recommended action

Investigate repeated unexpected timestamp rewinds.
