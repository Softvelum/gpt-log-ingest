# RTMP advertising content ends

Product: Nimble Streamer
Component: RTMP output and advertising
Logging function: log_d
Log level: debug
Documentation ID: log_d-1ec1c32915f37dc2

## Log pattern

```text
s=%d, stream_time=%lld %s content end, content_time=%lld
```

## Parameters

- Argument 1 — Socket: Operating-system socket descriptor for the affected connection.
- Argument 2 — Stream time: Current playback scheduling time in milliseconds.
- Argument 3 — Content URI: Configured URI of the selected advertising media item.
- Argument 4 — Content time: Advertising reader progress converted from 90 kHz ticks to milliseconds.

## Log examples

Illustrative examples; these are not captured server logs.

```text
s=42, stream_time=90000 https://media.example/ad.mp4 content end, content_time=30000
```

## Short description

RTMP advertising content ends.

## Trigger condition

The advertising reader reaches its end, or an eligible splice-in transition sends playback to the content-end phase.

## Explanation

The selected advertisement is released; live metadata and sequence headers will be resent and playback returns to waiting for scheduled content. A saved key frame can be substituted during live resumption.

## Possible causes

- The advertising reader reaches its end, or an eligible splice-in transition sends playback to the content-end phase.

## What to check

1. Check the actual content duration and any splice-in event when the end is unexpected.

## Recommended action

No action is required for an expected advertising end.
