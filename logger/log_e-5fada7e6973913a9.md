# WHIP frame header has no media payload

Product: Nimble Streamer
Component: WHIP publishing helper
Logging function: log_e
Log level: error
Documentation ID: log_e-5fada7e6973913a9

## Log pattern

```text
wrong frame sizes for session=%d, stream=[%s/%s]. Invalid header. entire message length=%d, frame info length=%d
```

## Parameters

- Argument 1 — Session identifier: WebRTC helper session identifier, unsigned 32-bit integer displayed in decimal; no unit.
- Argument 2 — Application: Application name, text.
- Argument 3 — Stream: Stream name, text.
- Argument 4 — Message length: Entire message-body length from the header, bytes, unsigned 32-bit integer displayed in decimal.
- Argument 5 — Information length: Frame-information length from the header, bytes, unsigned 32-bit integer displayed in decimal.

## Log examples

Illustrative examples; these are not captured server logs.

```text
wrong frame sizes for session=7, stream=[live/camera]. Invalid header. entire message length=40, frame info length=40
```

## Short description

WHIP frame header has no media payload.

## Trigger condition

The entire message length decoded from the WHIP media header is less than or equal to the declared frame-information length.

## Explanation

The media message is rejected and the caller removes the active publication and closes its socket.

## Possible causes

- The helper supplied inconsistent message lengths, leaving no positive media payload.

## What to check

1. Compare the total and information lengths and verify the helper version and framing.

## Recommended action

Correct the helper message framing and reconnect the publication.
