# SLDP advertising item ends

Product: Nimble Streamer
Component: SLDP playback and advertising
Logging function: log_d
Log level: debug
Documentation ID: log_d-d4e397c8659799fd

## Log pattern

```text
s=%d, video_sn=%d, audio_sn=%d %lld %s content end, content_time=%lld
```

## Parameters

- Argument 1 — Socket: Connection descriptor reported by the playback transport.
- Argument 2 — Video number: Client-assigned video stream number for this playback selection, or its default value when no video is selected.
- Argument 3 — Audio number: Client-assigned audio stream number for this playback selection, or its default value when no audio is selected.
- Argument 4 — Stream time: Playback scheduling time at the end, in milliseconds.
- Argument 5 — Content URI: Configured URI of the advertising media item.
- Argument 6 — Content time: Reader progress converted from 90 kHz ticks to milliseconds.

## Log examples

Illustrative examples; these are not captured server logs.

```text
s=42, video_sn=1, audio_sn=2 90000 https://media.example/ad.mp4 content end, content_time=30000
```

## Short description

SLDP advertising item ends.

## Trigger condition

The content reader reaches its end or an eligible splice-in event transitions playback to the content-end phase.

## Explanation

The item is released and the playback selection returns to waiting for scheduled advertising while live output resumes through its transition rules.

## Possible causes

- The content reader reaches its end or an eligible splice-in event transitions playback to the content-end phase.

## What to check

1. Check the content duration and any splice-in event if this end is unexpected.

## Recommended action

No action is required for an expected content end.
