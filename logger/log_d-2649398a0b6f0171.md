# HTTP/2 peer reset a stream

Product: Nimble Streamer
Component: HTTP/2 connection
Logging function: log_d
Log level: debug
Documentation ID: log_d-2649398a0b6f0171

## Log pattern

```text
[H2C::RE] p=%p st=%d s=%d strm=%lu err=%lu
```

## Parameters

- Argument 1 — Connection identity: In-process connection object address, pointer displayed in hexadecimal; useful only for correlating this process lifetime.
- Argument 2 — Connection state: Connection state code, integer: 0 awaiting preface, 1 awaiting settings, 2 sending settings/acknowledgment, 3 main processing, 4 sending GOAWAY, 5 shutting down, 6 stopped.
- Argument 3 — Socket: Socket descriptor, integer; no unit.
- Argument 4 — Reset stream identifier: HTTP/2 stream identifier from the frame, unsigned 32-bit value supplied to an unsigned-long decimal conversion.
- Argument 5 — Peer error code: Peer-supplied HTTP/2 reset error code, unsigned 32-bit value supplied to an unsigned-long decimal conversion; no unit.

The logged peer error code is recorded for diagnosis; removal behavior does not branch on its value. The two final conversions require unsigned long values, but both supplied values are unsigned 32-bit integers without a matching cast. This is not a portable printf argument match.

## Log examples

No reliable portable example can be asserted: both final unsigned-long conversions receive unsigned 32-bit arguments without the required matching type.

## Short description

HTTP/2 peer reset a stream.

## Trigger condition

A complete, structurally valid RST_STREAM frame is received for a previously opened stream identifier.

## Explanation

Nimble consumes the frame, cancels pending work for that stream when present, and stops its reply. Resets for absent streams increase a suspicious-reset counter; more than 100 consecutive such resets trigger a connection error.
