# Stream-check response buffer limit reached

Product: Nimble Streamer
Component: Linux stream availability checks
Logging function: log_e
Log level: error
Documentation ID: log_e-1b84ac086e1f87a5

## Log pattern

```text
StreamCheckerTask max buffer reached task='%s' s=%d
```

## Parameters

- Argument 1 — task: Panel-supplied stream-check task identifier.
- Argument 2 — socket: Socket descriptor for the stream-check connection.

## Log examples

Illustrative examples; these are not captured server logs.

```text
StreamCheckerTask max buffer reached task='check-a' s=12
```

## Short description

Stream-check response buffer limit reached.

## Trigger condition

Accumulated response input reaches the 32 KiB buffer limit without completing the earlier handling paths.

## Explanation

The task shuts down with a buffer-overflow status. For the non-RTMP result mapping, that status is treated as stream availability, so this error message does not necessarily produce an unavailable result.

## Possible causes

- The response filled the fixed stream-check buffer.

## What to check

1. Check response size and whether stream information can be recognized earlier.

## Recommended action

Review the monitored endpoint and its response size.
