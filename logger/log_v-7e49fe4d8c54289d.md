# Fragmented MP4 protocol time differs from accumulated time

Product: Nimble Streamer
Component: HLS and DASH packaging
Logging function: log_v
Log level: verbose
Documentation ID: log_v-7e49fe4d8c54289d

## Log pattern

```text
%s_%s_fmp4::hard_reset(%s, %llu, %llu)
```

## Parameters

- Argument 1 — Output kind: Packaging consumer label: dash, hls, or dvr.
- Argument 2 — Media: video or audio.
- Argument 3 — Stream: Stream label supplied to the segment builder.
- Argument 4 — Protocol time: New input timestamp in track-timescale ticks.
- Argument 5 — Accumulated time: Calculated track timestamp in the same timescale.

## Log examples

Illustrative examples; these are not captured server logs.

```text
hls_audio_fmp4::hard_reset(live/camera, 1000, 480000)
```

## Short description

Fragmented MP4 protocol time differs from accumulated time.

## Trigger condition

Protocol-time reset detection is enabled, the check is not suppressed, and the new input timestamp differs from the accumulated timestamp.

## Explanation

A protocol-time-reset flag is set for the caller to handle. This message alone does not determine the caller recovery action.

## Possible causes

- Protocol-time reset detection is enabled, the check is not suppressed, and the new input timestamp differs from the accumulated timestamp.

## What to check

1. Compare source timestamp continuity with the expected accumulated track time.

## Recommended action

Investigate unexpected source timestamp changes.
