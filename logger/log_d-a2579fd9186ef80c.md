# Input exceeds the strict maximum resolution

Product: Nimble Streamer
Component: Transcoder orchestration
Logging function: log_d
Log level: debug
Documentation ID: log_d-a2579fd9186ef80c

## Log pattern

```text
input filtered as stream resolution=%lldx%lld is '>=' %lldx%lld for [%s/%s]
```

## Parameters

- Argument 1 — Input width: Input video width, 64-bit integer pixels.
- Argument 2 — Input height: Input video height, 64-bit integer pixels.
- Argument 3 — Filter width: Configured comparison width, 64-bit integer pixels.
- Argument 4 — Filter height: Configured comparison height, 64-bit integer pixels.
- Argument 5 — Application: Application name, text.
- Argument 6 — Stream: Stream name, text.

The comparison rejects on either dimension; it does not require both dimensions to fail. For strict maximum, maximum and equality filters, a zero configured dimension disables that dimension. The resolution arguments are fixed-width 64-bit values passed to signed long-long conversions without casts. These types differ on platforms where the 64-bit typedef uses long.

## Log examples

The resolution arguments are fixed-width 64-bit values passed to signed long-long conversions without casts. These types differ on platforms where the 64-bit typedef uses long. A reliable example is omitted because the original call does not ensure matching printf argument types.

## Short description

Input exceeds the strict maximum resolution.

## Trigger condition

The input must be smaller than the configured resolution, but at least one enabled dimension is greater than or equal to its limit.

## Explanation

The input fails the resolution filter and is skipped for the affected transcoding settings.

## Possible causes

- The source resolution does not satisfy the configured comparison.

## What to check

1. Compare the reported dimensions with the intended input-resolution filter.

## Recommended action

No action is needed when the exclusion is intentional; otherwise adjust the filter or source resolution.
