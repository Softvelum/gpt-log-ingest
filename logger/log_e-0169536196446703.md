# DRM key request failed and retry is evaluated

Product: Nimble Streamer
Component: DRM key management
Logging function: log_e
Log level: error
Documentation ID: log_e-0169536196446703

## Log pattern

```text
failed to get %s DRM keys for='%s' cpi=%u/%u url='%s' retry=%u %s
```

## Parameters

- Argument 1 — Provider: Text naming the DRM provider.
- Argument 2 — Key owner: Text identifying the application or application/stream whose keys are managed.
- Argument 3 — Crypto-period index: Unsigned index of the requested or selected key rotation period.
- Argument 4 — Period count: Unsigned number of consecutive crypto periods requested.
- Argument 5 — Key-server URL: Text giving the configured or requested key-server URL.
- Argument 6 — Retry index: Unsigned retry number; zero is the initial request.
- Argument 7 — HTTP response details: Text containing the HTTP status and optional response body; empty when no response parser exists.

## Log examples

Illustrative examples; these are not captured server logs.

```text
failed to get Widevine DRM keys for='live/camera' cpi=120/2 url='https://keys.example/key' retry=0 status=503 body='unavailable'
```

## Short description

DRM key request failed and retry is evaluated.

## Trigger condition

A managed provider key request receives a failure callback.

## Explanation

Retries 1 through 3 are attempted while settings and key slots remain available; failure at retry 3, or missing settings or slots, marks the affected keys failed and notifies waiting consumers.

## Possible causes

- A managed provider key request receives a failure callback.

## What to check

1. Check provider availability, credentials, and response details; compare the retry index to the final attempt.

## Recommended action

Check provider availability, credentials, and response details; compare the retry index to the final attempt.
