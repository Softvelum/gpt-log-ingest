# HTTP file response read incomplete

Product: Nimble Streamer
Component: HTTP file response
Logging function: log_e
Log level: error
Documentation ID: log_e-3a269f5036dc5e0b

## Log pattern

```text
failed to read %llu bytes from fd=%d offset=%ld errno=%d read=%lld
```

## Parameters

- Argument 1 — Requested bytes: Requested read length, unsigned byte count; a 64-bit count for HTTP replies and a size-based count capped at 131,072 bytes for TLS file sending.
- Argument 2 — File descriptor: Open input file descriptor, integer; no unit.
- Argument 3 — Reported offset: HTTP response range start plus bytes already sent, or the absolute TLS file-send offset, bytes. For DVR replies the displayed HTTP offset does not include the archive segment base.
- Argument 4 — Operating system error: C runtime errno value immediately after the failed operation, integer; no unit.
- Argument 5 — Read result: Signed number of bytes returned by the file read; zero means end-of-file and minus one means a read error.

Both short reads and read errors log errno; a short successful read can leave an unrelated earlier errno value. The requested-length and read-result conversions require unsigned long-long and signed long-long values, respectively. The calls instead supply fixed-width or size-based counts and a signed size-based read result; their underlying types can differ from those conversions.

## Short description

HTTP file response read incomplete.

## Trigger condition

A file read returns a count different from the number of bytes requested.

## Explanation

The HTTP/2 or HTTP/3 file-read operation fails; in the TLS file-send path the call returns a send failure before writing these bytes to TLS.

## Possible causes

- The file has reached an unexpected end, a short read occurs, or the operating system reports a read error.

## What to check

1. Compare requested and actual counts and check whether the file changed or the storage read failed.

## Recommended action

Restore a complete readable response file and retry.
