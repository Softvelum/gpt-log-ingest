# Failed fragmented item remained after cleanup

Product: Nimble Streamer
Component: Media data cache
Logging function: log_e
Log level: error
Documentation ID: log_e-616ae55ca7090d78

## Log pattern

```text
cache item key='%s' remained in cache after removing the last fragment
```

## Parameters

- Argument 1 — key: Cache lookup key identifying the stored item.

## Log examples

Illustrative examples; these are not captured server logs.

```text
cache item key='movie' remained in cache after removing the last fragment
```

## Short description

Failed fragmented item remained after cleanup.

## Trigger condition

A marked, unused fragmented item still exists after its first fragment is removed during replacement.

## Explanation

The reservation reports an existing item and does not create a replacement. The message calls it the last fragment because this recovery path expects a single failed fragment.

## Possible causes

- Removing the expected single failed fragment did not remove the parent item.

## What to check

1. Compare fragment availability and prior removal messages for the key.

## Recommended action

Investigate the remaining fragmented cache state.
