# Metadata removed after a backward timestamp jump

Product: Nimble Streamer
Component: Decoder metadata synchronization
Logging function: log_i
Log level: info
Documentation ID: log_i-b128c28384bd3c06

## Log pattern

```text
backward gap detected, removed item with dts=%lld pts=%lld for [%s], dts=%lld pts=%lld
```

## Parameters

- Argument 1 — Removed decode timestamp: Decode timestamp of the removed metadata item, signed 64-bit ticks in the associated video time base.
- Argument 2 — Queued presentation timestamp: Presentation timestamp of the queued metadata item, signed 64-bit ticks in the associated video time base.
- Argument 3 — Stream: Input stream name, text.
- Argument 4 — Incoming decode timestamp: Decode timestamp of the new metadata item, unsigned 64-bit ticks printed in decimal in the same video time base.
- Argument 5 — Incoming presentation timestamp: Presentation timestamp of the new metadata item, unsigned 64-bit ticks printed in decimal in the same video time base.

The timestamp arguments use fixed-width 64-bit types without casts to the signed long-long conversions. On platforms where those types use long, the printf types differ; incoming unsigned timestamps also require a representable signed value.

## Short description

Metadata removed after a backward timestamp jump.

## Trigger condition

Adding caption or SEI-timecode metadata finds a queued item with a decode timestamp greater than the incoming decode timestamp.

## Explanation

Each such queued item is removed before the new item is inserted by presentation time.

## Possible causes

- The input decode timeline moved backward relative to pending metadata.

## What to check

1. Compare incoming and removed timestamps using the video time base and check source discontinuities.

## Recommended action

Correct unexpected timestamp discontinuities; the queue already discards metadata from the obsolete future timeline.
