# Transmuxer caught a bus signal

Product: Nimble Streamer
Component: VOD transmuxing
Logging function: log_i
Log level: info
Documentation ID: log_i-651ef91257c22c8e

## Log pattern

```text
signal handler: %s (%d) si_code=%d si_addr=0x%x
```

## Parameters

- Argument 1 — Signal description: Text returned by the operating system for the signal.
- Argument 2 — Signal number: Integer signal number.
- Argument 3 — Signal code: Integer operating-system cause code from the signal information.
- Argument 4 — Fault address: Pointer address of the faulting memory access, incorrectly printed with %x.

The fault address is a pointer passed to %x, which expects unsigned int. That field is unreliable and can be truncated, so no exact example is provided.

## Short description

Transmuxer caught a bus signal.

## Trigger condition

On non-Windows builds, the installed bus-signal handler receives a signal during protected mapped-media processing.

## Explanation

The handler logs signal details and jumps back to the saved recovery point, where the current request is abandoned and relevant resources are cleaned up.

## Possible causes

- On non-Windows builds, the installed bus-signal handler receives a signal during protected mapped-media processing.

## What to check

1. Check whether a mapped media file was truncated or changed and inspect storage I/O errors; the signal detail identifies the failed access.
