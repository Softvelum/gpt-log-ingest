# Legacy RTMP video codec changes midstream

Product: Nimble Streamer
Component: RTMP media input
Logging function: log_e
Log level: error
Documentation ID: log_e-464a19e7d44397cb

## Log pattern

```text
[VM] video codec changed %d->%d
```

## Parameters

- Argument 1 — Previous video codec: Numeric video format already established for this message stream.
- Argument 2 — New video codec: Numeric codec ID from the current legacy video tag.

## Log examples

Illustrative examples; these are not captured server logs.

```text
[VM] video codec changed 7->12
```

## Short description

Legacy RTMP video codec changes midstream.

## Trigger condition

A supported legacy video tag codec differs from the established video format for the message stream.

## Explanation

The changed video message is rejected and connection processing fails.

## Possible causes

- A supported legacy video tag codec differs from the established video format for the message stream.

## What to check

1. Compare the first and current video tag codec IDs.

## Recommended action

Keep the video codec consistent during the connection or restart publication for a codec change.
