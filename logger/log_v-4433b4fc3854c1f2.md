# Fragmented MP4 timing is adjusted after an associated-track rewind

Product: Nimble Streamer
Component: HLS and DASH packaging
Logging function: log_v
Log level: verbose
Documentation ID: log_v-4433b4fc3854c1f2

## Log pattern

```text
%s_%s_fmp4_overrun::reset(%s, %llu, %llu, %llu, %llu, %llu)
```

## Parameters

- Argument 1 — Output kind: Packaging consumer label: dash, hls, or dvr.
- Argument 2 — Media: video or audio.
- Argument 3 — Stream: Stream label supplied to the segment builder.
- Argument 4 — Protocol time: New input timestamp in track-timescale ticks.
- Argument 5 — Previous accumulated time: Accumulated track timestamp before this correction, in the same ticks.
- Argument 6 — Adjusted time: Replacement accumulated track timestamp in the same ticks.
- Argument 7 — Associated accumulated time: Associated track time supplied for alignment, in the same ticks.
- Argument 8 — Associated rewind point: Associated track protocol timestamp at its rewind, in the same ticks.

## Log examples

Illustrative examples; these are not captured server logs.

```text
dash_video_fmp4_overrun::reset(live/camera, 1000, 900000, 901000, 900000, 0)
```

## Short description

Fragmented MP4 timing is adjusted after an associated-track rewind.

## Trigger condition

Protocol-time reset is disabled, the new protocol timestamp goes backward, and an associated track has supplied rewind information with the same timescale that yields a nonnegative replacement time.

## Explanation

The accumulated segment time is replaced with the associated current time plus the new protocol time minus the associated rewind point. Segment sample state is then reset for the next segment.

## Possible causes

- Protocol-time reset is disabled, the new protocol timestamp goes backward, and an associated track has supplied rewind information with the same timescale that yields a nonnegative replacement time.

## What to check

1. Compare both track timestamps and the associated rewind values.

## Recommended action

Investigate repeated unexpected source timestamp resets.
