# HTTP response parsing progress

Product: Nimble Streamer
Component: HTTP media delivery
Logging function: log_d
Log level: debug
Documentation ID: log_d-1e974ca9d72a1f23

## Log pattern

```text
[HReP::Pa] hc=%d st=%hu r=%hhd
```

## Parameters

- Argument 1 — Headers complete: Boolean header-completion flag, printed as 0 or 1.
- Argument 2 — Status: Parsed HTTP status code, possibly zero before it is available.
- Argument 3 — Ready: Boolean message-completion flag, printed as 0 or 1.

## Log examples

Illustrative examples; these are not captured server logs.

```text
[HReP::Pa] hc=1 st=200 r=0
```

## Short description

HTTP response parsing progress.

## Trigger condition

The response parser consumes the entire supplied buffer and diagnostic output has not been suppressed.

## Explanation

The log reports header completion, parsed status, and message completion. A successful parse of this buffer can still leave the overall response incomplete.

## Possible causes

- The response parser consumes the entire supplied buffer and diagnostic output has not been suppressed.

## What to check

1. Check the completion flags before assuming the entire response arrived.
