# DVB subtitle payload is too short for decoding

Product: Nimble Streamer
Component: Live media packaging and timed metadata
Logging function: log_e
Log level: error
Documentation ID: log_e-1e4c7f778070fab5

## Log pattern

```text
invalid dvb_subtitle_size=%d for [%s/%s]
```

## Parameters

- Argument 1 — Payload size: Received DVB subtitle payload bytes, including its transport prefix and suffix.
- Argument 2 — Application: Application containing the live stream.
- Argument 3 — Stream: Live stream name.

## Log examples

Illustrative examples; these are not captured server logs.

```text
invalid dvb_subtitle_size=3 for [live/camera]
```

## Short description

DVB subtitle payload is too short for decoding.

## Trigger condition

DVB-to-WebVTT processing receives at most three bytes after a valid subtitle descriptor has been accepted.

## Explanation

The subtitle is rejected before the transport prefix and suffix can be removed or the message added to synchronization.

## Possible causes

- DVB-to-WebVTT processing receives at most three bytes after a valid subtitle descriptor has been accepted.

## What to check

1. Check DVB subtitle payload framing and length.

## Recommended action

Provide complete DVB subtitle payloads.
