# WebRTC helper welcome exceeds declared length

Product: Nimble Streamer
Component: WebRTC helper connection
Logging function: log_d
Log level: debug
Documentation ID: log_d-5eca206003f17964

## Log pattern

```text
wrong welcome message size. fd=%d, declared size=%d, actual size=%d
```

## Parameters

- Argument 1 — Socket: Socket descriptor, integer; no unit.
- Argument 2 — Declared length: Welcome body length from the header, bytes, unsigned 32-bit value cast to int.
- Argument 3 — Actual length: Accumulated welcome body length, bytes, size converted to int.

Both the WHIP and WHEP listeners use this same equality check after buffering the welcome body.

## Log examples

Illustrative examples; these are not captured server logs.

```text
wrong welcome message size. fd=12, declared size=100, actual size=120
```

## Short description

WebRTC helper welcome exceeds declared length.

## Trigger condition

Accumulated bytes after the four-byte welcome header exceed the body length declared by a WHIP or WHEP helper.

## Explanation

The newly accepted socket is removed from monitoring and discarded; the welcome is not accepted.

## Possible causes

- The helper length prefix does not match the bytes received, or extra bytes arrive in the welcome buffer.

## What to check

1. Compare the declared and actual lengths and verify the helper message framing.

## Recommended action

Correct the helper message framing before reconnecting.
