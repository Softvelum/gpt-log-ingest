# NVIDIA decoder cannot accept a sequence change

Product: Nimble Streamer
Component: NVIDIA video decoding
Logging function: log_e
Log level: error
Documentation ID: log_e-ebd20189772a62d6

## Log pattern

```text
failed to reinit nvidia encoder from w:%d h:%d fmt:%d to w:%d h:%d fmt:%d for [%s] 
```

## Parameters

- Argument 1 — Old width: Previous display-area right coordinate used as output width, integer pixels.
- Argument 2 — Old height: Previous display-area bottom coordinate used as output height, integer pixels.
- Argument 3 — Old chroma: Previous NVIDIA chroma-format identifier, integer.
- Argument 4 — New width: New display-area right coordinate, integer pixels.
- Argument 5 — New height: New display-area bottom coordinate, integer pixels.
- Argument 6 — New chroma: New NVIDIA chroma-format identifier, integer.
- Argument 7 — Stream: Input stream name, text.

## Log examples

Illustrative examples; these are not captured server logs.

```text
failed to reinit nvidia encoder from w:1920 h:1080 fmt:1 to w:1280 h:720 fmt:1 for [live/camera] 
```

## Short description

NVIDIA decoder cannot accept a sequence change.

## Trigger condition

An existing decoder sees a sequence with a changed codec, chroma format, coded width or coded height.

## Explanation

Reinitialization is unsupported here: the callback marks an error and packet processing fails. Despite saying encoder, this message comes from decoding.

## Possible causes

- The input changes codec, chroma format or coded dimensions while a decoder is active.

## What to check

1. Check source sequence changes. The logged dimensions are display-area right/bottom values, so a coded-size or codec change can occur even when the printed values look unchanged.

## Recommended action

Restart decoding for the changed stream or keep its sequence parameters stable.
