# HTTP file response seek failed

Product: Nimble Streamer
Component: HTTP file response
Logging function: log_e
Log level: error
Documentation ID: log_e-26355e8e9fe33e29

## Log pattern

```text
failed to seek to offset=%lld for fd=%d errno=%d
```

## Parameters

- Argument 1 — Target offset: Absolute byte offset requested in the open file, 64-bit file offset displayed in decimal.
- Argument 2 — File descriptor: Open input file descriptor, integer; no unit.
- Argument 3 — Operating system error: C runtime errno value immediately after the failed operation, integer; no unit.

Occurrences seek to a normal range start, a DVR subtitle/media segment header, the adjusted DVR segment plus range start, or the current TLS file-send offset. The errno field is reliable as the immediate error only when the seek itself reports failure. The offset argument is a 64-bit file position supplied to a signed long-long conversion without a cast. These types differ on platforms where file offsets use signed long.

## Log examples

The offset argument is a 64-bit file position supplied to a signed long-long conversion without a cast. These types differ on platforms where file offsets use signed long. A reliable example is omitted because the original call does not ensure matching printf argument types.

## Short description

HTTP file response seek failed.

## Trigger condition

Seeking an open response file does not return the exact requested byte offset.

## Explanation

Local/DVR response preparation returns failure with an internal-server-error status. In the TLS file-send path, sending fails with an invalid-argument transport error and no file data is written by this call.

## Possible causes

- The operating system rejects the seek or the file descriptor cannot be positioned as required.

## What to check

1. Use the file descriptor, requested offset, and operating system error to inspect the affected response file.

## Recommended action

Correct the file or storage problem and retry the request.
