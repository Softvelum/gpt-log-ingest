# WebSocket accept hash failed

Product: Nimble Streamer
Component: HTTP client sessions
Logging function: log_e
Log level: error
Documentation ID: log_e-2643929e80872487

## Log pattern

```text
Utils::Sha1Hash failed for s='%s'
```

## Parameters

- Argument 1 — Hash input: Text formed from Sec-WebSocket-Key followed by the fixed WebSocket GUID.

## Log examples

Illustrative examples; these are not captured server logs.

```text
Utils::Sha1Hash failed for s='dGhlIHNhbXBsZSBub25jZQ==258EAFA5-E914-47DA-95CA-C5AB0DC85B11'
```

## Short description

WebSocket accept hash failed.

## Trigger condition

Hashing the client WebSocket key concatenated with the standard accept GUID returns an empty result.

## Explanation

An HTTP 500 response is prepared instead of a WebSocket upgrade.

## Possible causes

- Hashing the client WebSocket key concatenated with the standard accept GUID returns an empty result.

## What to check

1. Check nearby cryptographic errors; the server could not construct the handshake accept value.

## Recommended action

Check nearby cryptographic errors; the server could not construct the handshake accept value.
