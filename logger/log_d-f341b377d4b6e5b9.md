# DVR export pads the media-data gap

Product: Nimble Streamer
Component: DVR export
Logging function: log_d
Log level: debug
Documentation ID: log_d-f341b377d4b6e5b9

## Log pattern

```text
added %d extra bytes into video only mdat stream=%s utc_start=%lld utc_end=%lld
```

## Parameters

- Argument 1 — Padding bytes: 64-bit number of padding bytes required.
- Argument 2 — Stream: Text naming the application and stream.
- Argument 3 — UTC start: 64-bit requested UTC start in seconds since the Unix epoch; zero leaves this bound unspecified.
- Argument 4 — UTC end: 64-bit requested UTC end in seconds since the Unix epoch; zero leaves this bound unspecified.

Padding is a 64-bit value passed to a 32-bit integer conversion. The wording says video only even at the audio-only occurrence.

## Log examples

No sound example is given because the padding count does not match its printf conversion.

## Short description

DVR export pads the media-data gap.

## Trigger condition

The video-only or audio-only sample payload ends before the previously calculated movie-metadata offset.

## Explanation

The gap is filled with padding before movie metadata is sent.

## Possible causes

- The video-only or audio-only sample payload ends before the previously calculated movie-metadata offset.

## What to check

1. Check skipped segments if padding was unexpected.

Check skipped segments if padding was unexpected.
