# RTMP playback restarts after falling behind

Product: Nimble Streamer
Component: RTMP output and advertising
Logging function: log_e
Log level: error
Documentation ID: log_e-66efd37b005e86d6

## Log pattern

```text
failed to send stream in appropriate rate(start sending new items). s=%d ip=%s stream='%s/%s'
```

## Parameters

- Argument 1 — Socket: Operating-system socket descriptor for the affected connection.
- Argument 2 — Client IP: Connected playback peer address.
- Argument 3 — Application: Requested playback application.
- Argument 4 — Stream: Requested playback stream name.

## Log examples

Illustrative examples; these are not captured server logs.

```text
failed to send stream in appropriate rate(start sending new items). s=42 ip=192.0.2.30 stream='live/camera'
```

## Short description

RTMP playback restarts after falling behind.

## Trigger condition

The playback position requests media that is older than the retained stream-buffer range.

## Explanation

Metadata and sequence-header positions are reset, output is temporarily disabled, and playback prepares to start from fresh media and a key frame. This branch does not itself close the connection unless changing output events fails.

## Possible causes

- The playback position requests media that is older than the retained stream-buffer range.

## What to check

1. Check client receive speed, network capacity, and the source media rate.

## Recommended action

Restore enough receive capacity to prevent repeated playback resets.
