# Remote media response range or size is inconsistent

Product: Nimble Streamer
Component: Remote media cache requests
Logging function: log_e
Log level: error
Documentation ID: log_e-106881f1f2758381

## Log pattern

```text
invalid state for url='%s' capacity=%llu range_from=%llu range_to=%llu content_length=%lld body_len=%lld
```

## Parameters

- Argument 1 — key: Cache key, also used as the remote request URL.
- Argument 2 — capacity: Total item capacity in bytes.
- Argument 3 — from: Inclusive starting byte offset.
- Argument 4 — to: Exclusive ending byte offset.
- Argument 5 — content length: Selected response content length in bytes.
- Argument 6 — body length: Parsed response body size in bytes.

## Log examples

Illustrative examples; these are not captured server logs.

```text
invalid state for url='https://media.example/movie.mp4' capacity=2097152 range_from=0 range_to=1048576 content_length=512 body_len=512
```

## Short description

Remote media response range or size is inconsistent.

## Trigger condition

A GET response range exceeds item capacity, its length differs from the requested range, or its body size differs from that length.

## Explanation

The item reference and active request are released without copying data or marking the fragment available. This branch does not explicitly mark the fragment failed.

## Possible causes

- The origin response does not match the requested byte range or cached item size.

## What to check

1. Compare all reported range and length values.

## Recommended action

Correct origin byte-range handling or investigate changed remote media.
