# Failed media mapping is being released

Product: Nimble Streamer
Component: VOD transmuxing
Logging function: log_i
Log level: info
Documentation ID: log_i-67c7ba4a9a34d797

## Log pattern

```text
unmapping p=%p len=%zu f=%d size=%ld mtime=%ld
```

## Parameters

- Argument 1 — Mapping address: Pointer to the mapped input bytes.
- Argument 2 — Mapped bytes: Native-size unsigned mapping length in bytes.
- Argument 3 — File descriptor: Integer input-file descriptor.
- Argument 4 — Actual file bytes: Signed file size in bytes from the recovery metadata lookup, or zero on lookup failure.
- Argument 5 — File modification time: Epoch seconds from the recovery metadata lookup, or zero on failure.

Size and time are printed with %ld; the example assumes a platform where file offsets and time_t fit signed long.

## Log examples

Illustrative examples; these are not captured server logs.

```text
unmapping p=0x1234 len=1048576 f=23 size=524288 mtime=1790596800
```

## Short description

Failed media mapping is being released.

## Trigger condition

Bus-signal recovery has a local mapped media object to clean up.

## Explanation

The mapping and file metadata are logged immediately before unmapping and closing. Size and modification time remain zero if metadata lookup failed.

## Possible causes

- Bus-signal recovery has a local mapped media object to clean up.

## What to check

1. Compare mapped length with current file size and examine source replacement or truncation.

## Recommended action

Compare mapped length with current file size and examine source replacement or truncation.
