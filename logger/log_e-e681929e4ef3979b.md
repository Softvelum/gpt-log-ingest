# Fragmented cache item retained after metadata failure

Product: Nimble Streamer
Component: Media data cache
Logging function: log_e
Log level: error
Documentation ID: log_e-e681929e4ef3979b

## Log pattern

```text
skip deleting fragmented item='%s' sz=%llu cap=%llu
```

## Parameters

- Argument 1 — key: Cache lookup key identifying the stored item.
- Argument 2 — size: Stored data size in bytes.
- Argument 3 — capacity: Allocated capacity of the item in bytes.

## Log examples

Illustrative examples; these are not captured server logs.

```text
skip deleting fragmented item='movie' sz=1048576 cap=2097152
```

## Short description

Fragmented cache item retained after metadata failure.

## Trigger condition

An unused fragmented item has been unmapped, but saving its metadata fails.

## Explanation

Unlike a normal file-backed item, this fragmented item is deliberately retained rather than deleting its files here.

## Possible causes

- Metadata saving failed for a fragmented cache item.

## What to check

1. Find the preceding metadata creation, write, or close error.

## Recommended action

Correct the metadata storage failure and assess whether the retained fragments remain usable.
