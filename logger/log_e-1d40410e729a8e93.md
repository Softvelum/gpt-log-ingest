# HLS input sequence position reset

Product: Nimble Streamer
Component: HLS and MPEG-TS HTTP input
Logging function: log_e
Log level: error
Documentation ID: log_e-1d40410e729a8e93

## Log pattern

```text
media sequence reset for url='%s' prev=%u new=%u current=%u chunks=%u
```

## Parameters

- Argument 1 — original\_url: Original configured input URL.
- Argument 2 — previous\_sequence: Previous nonzero stored sequence.
- Argument 3 — reset\_sequence: New stored sequence position before subsequent increments.
- Argument 4 — playlist\_first\_sequence: First sequence advertised by this playlist.
- Argument 5 — segment\_count: Number of segments found in the playlist.

The final segment count is size_t but %u expects unsigned int; this can mismatch on 64-bit targets.

## Log examples

No portable full example is supplied because the final argument type does not match its conversion.

## Short description

HLS input sequence position reset.

## Trigger condition

A nonzero stored sequence is outside the range of segments advertised by the current playlist.

## Explanation

The stored position is reset to one below the playlist last sequence when that last sequence exceeds one, otherwise zero. Subsequent queuing starts at the next sequence, close to the live edge. This is logged only when the old stored sequence was nonzero.

## Possible causes

- The playlist window moved beyond the stored position or its numbering changed.

## What to check

1. Compare the previous position with the current playlist sequence window.

## Recommended action

Check source playlist continuity if these resets are unexpected.
