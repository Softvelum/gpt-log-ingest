# Video frame properties changed after initialization

Product: Nimble Streamer
Component: Video format continuity
Logging function: log_e
Log level: error
Documentation ID: log_e-f46aa8551c3686f2

## Log pattern

```text
failed to change frame properties from %dx%d/%d to %dx%d/%d on the fly for [%s]
```

## Parameters

- Argument 1 — Previous width: Initialized width in pixels, integer.
- Argument 2 — Previous height: Initialized height in pixels, integer.
- Argument 3 — Previous format: Initialized FFmpeg pixel-format identifier, integer.
- Argument 4 — New width: Incoming width in pixels, integer.
- Argument 5 — New height: Incoming height in pixels, integer.
- Argument 6 — New format: Incoming FFmpeg pixel-format identifier, integer.
- Argument 7 — Input or stream: Filter input label for video filtering; stream name for x264 encoding, text.

The final text is a filter input label in filtering and a stream name in x264 encoding.

## Log examples

Illustrative examples; these are not captured server logs.

```text
failed to change frame properties from 1920x1080/0 to 1280x720/0 on the fly for [live/camera]
```

## Short description

Video frame properties changed after initialization.

## Trigger condition

An initialized video filter input or x264 encoder receives a frame whose width, height, or pixel format differs from its retained properties.

## Explanation

The frame write returns failure instead of changing the active input or encoder in place.

## Possible causes

- The upstream video dimensions or format changed.

## What to check

1. Compare old and new dimensions and pixel formats.

## Recommended action

Keep video properties stable or recreate the affected filter or encoder.
