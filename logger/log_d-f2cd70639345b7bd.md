# HLS chunk cache insertion is attempted

Product: Nimble Streamer
Component: HLS and DASH packaging
Logging function: log_d
Log level: debug
Documentation ID: log_d-f2cd70639345b7bd

## Log pattern

```text
add_chunk key='%s' duration=%d,%d size=%d
```

## Parameters

- Argument 1 — Cache key: Application/stream path and generated segment or part name used as the cache identity.
- Argument 2 — Whole seconds: Intended duration whole seconds; its 64-bit value does not match the 32-bit conversion.
- Argument 3 — Milliseconds: Intended duration fractional milliseconds; its 64-bit value does not match the 32-bit conversion.
- Argument 4 — Size: Payload size in bytes.

## Log examples

No reliable complete example is available because both duration arguments have a 64-bit/32-bit formatting mismatch.

## Short description

HLS chunk cache insertion is attempted.

## Trigger condition

A generated chunk key and payload are about to be reserved in the cache.

## Explanation

The log precedes reservation and storage, so it does not confirm success. The duration arguments are 64-bit values passed to 32-bit conversions and their printed values are unreliable.

## Possible causes

- A generated chunk key and payload are about to be reserved in the cache.

## What to check

1. Check subsequent cache reservation/allocation errors for the key.

## Recommended action

No action is required when the item is successfully cached.
