# Pay-per-view identity differs from the session

Product: Nimble Streamer
Component: Playback session tracking
Logging function: log_e
Log level: error
Documentation ID: log_e-8f522d49238ab372

## Log pattern

```text
ppv client %s[ppv_id=%s] tried to use ppv_id=%s
```

## Parameters

- Argument 1 — client: Client IP address.
- Argument 2 — saved identity: Pay-per-view client identity stored when the session was registered.
- Argument 3 — current identity: Identity obtained from the current access check.

## Log examples

Illustrative examples; these are not captured server logs.

```text
ppv client 192.0.2.10[ppv_id=viewer-a] tried to use ppv_id=viewer-b
```

## Short description

Pay-per-view identity differs from the session.

## Trigger condition

Access checking returns a pay-per-view client identity different from the one saved for this session.

## Explanation

Session validation fails and reports access failure. The text describes an identity mismatch; it does not prove deliberate misuse.

## Possible causes

- The current access credentials resolve to a different pay-per-view client.

## What to check

1. Compare the client identity and session identifier used for successive requests.

## Recommended action

Use the session with the matching pay-per-view identity.
