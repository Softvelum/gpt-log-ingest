# Video filter resets after a timestamp jump

Product: Nimble Streamer
Component: Video filtering
Logging function: log_e
Log level: error

## Log pattern

```text
reset video filter on pts gap(prev=%lld, cur=%lld, timescale=%d/%d), filter=%s, stream=%s
```

## Parameters

- Argument 1 — Previous timestamp: Previous input presentation timestamp, signed 64-bit ticks in the input time base.
- Argument 2 — Current timestamp: Current input presentation timestamp, signed 64-bit ticks in the printed time base.
- Argument 3 — Time-base numerator: Seconds-per-tick rational numerator, integer.
- Argument 4 — Time-base denominator: Seconds-per-tick rational denominator, integer.
- Argument 5 — Filter: Configured filter identifier, text.
- Argument 6 — Input: Input stream name, text.

The timestamps are signed 64-bit values passed to signed long-long conversions without casts. These types differ on platforms where the 64-bit typedef is signed long.

## Short description

Video filter resets after a timestamp jump.

## Trigger condition

Timestamp-gap checking is enabled and the rounded difference between consecutive input timestamps exceeds positive or negative 60 seconds; the expression contains fps= or overlay timestamp adjustment is enabled.

## Explanation

The filter is recreated, input links are reset to it, and output links are refreshed before processing the current frame.

## Possible causes

- The source presentation timestamp jumps substantially forward or backward.

## What to check

1. Compare the reported timestamps using the supplied time base and check source restart or discontinuity events.

## Recommended action

Correct unexpected timestamp discontinuities; the filter already resets its processing state.
