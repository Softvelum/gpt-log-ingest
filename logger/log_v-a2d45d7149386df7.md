# Constant-rate output queue is full

Product: Nimble Streamer
Component: MPEG-TS transport input and output
Logging function: log_v
Log level: verbose
Documentation ID: log_v-a2d45d7149386df7

## Log pattern

```text
cbr list size exhausted for [%s:%d], size=%lld
```

## Parameters

- Argument 1 — Destination: Configured destination IP address.
- Argument 2 — Port: Configured destination port.
- Argument 3 — Queue limit: Maximum datagram count, also the threshold reached here.

## Log examples

Illustrative examples; these are not captured server logs.

```text
cbr list size exhausted for [192.0.2.20:5000], size=100
```

## Short description

Constant-rate output queue is full.

## Trigger condition

The queue has reached its calculated maximum datagram count while another complete transport datagram is ready to enqueue.

## Explanation

Enqueueing stops and returns failure. Already queued datagrams are retained and the muxing loop enters shutdown.

## Possible causes

- The queue has reached its calculated maximum datagram count while another complete transport datagram is ready to enqueue.

## What to check

1. Check queue duration, configured mux rate, and sending throughput.

## Recommended action

Resolve the rate/buffer mismatch or stalled sending path.
