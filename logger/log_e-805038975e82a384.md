# RTMP input buffer cannot accommodate the chunk size

Product: Nimble Streamer
Component: RTMP connection transport
Logging function: log_e
Log level: error
Documentation ID: log_e-805038975e82a384

## Log pattern

```text
failed to allocate RTMP buffer for stream='%s' s=%d size=%u allocated=%u, try adding 'rtmp_max_chunksize_enabled = true' to nimble.conf
```

## Parameters

- Argument 1 — Stream: Stream identity returned by the connection; outbound pulling can show its RTMP URL.
- Argument 2 — Socket: Operating-system socket descriptor for this connection.
- Argument 3 — Requested size: Required incoming-buffer capacity in bytes.
- Argument 4 — Allocated size: Incoming-buffer capacity in bytes before the growth attempt.

## Log examples

Illustrative examples; these are not captured server logs.

```text
failed to allocate RTMP buffer for stream='rtmp://origin.example:1935/live/camera' s=42 size=8454162 allocated=4194304, try adding 'rtmp_max_chunksize_enabled = true' to nimble.conf
```

## Short description

RTMP input buffer cannot accommodate the chunk size.

## Trigger condition

The incoming buffer cannot grow to the larger of its current allocation and the negotiated chunk size plus 65,554 bytes of framing/read allowance.

## Explanation

The connection is shut down before reading more chunks. The normal buffer limit is 4 MiB; the compatibility setting named in the message permits the maximum RTMP chunk size plus the allowance. Allocation failure can also cause this message.

## Possible causes

- The incoming buffer cannot grow to the larger of its current allocation and the negotiated chunk size plus 65,554 bytes of framing/read allowance.

## What to check

1. Compare the requested and allocated sizes with the peer chunk size, the maximum-chunk-size setting, and available memory.

## Recommended action

Use a smaller peer chunk size, or enable the named compatibility setting when that large chunk size is intentional and memory capacity allows it.
