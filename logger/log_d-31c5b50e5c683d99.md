# SLDP aligns audio and video advertising timestamps

Product: Nimble Streamer
Component: SLDP playback and advertising
Logging function: log_d
Log level: debug
Documentation ID: log_d-31c5b50e5c683d99

## Log pattern

```text
s=%d, video_sn=%d, audio_sn=%d %s content start, initial_video_timestamp=%lld, initial_audio_timestamp=%lld, offset=%lld
```

## Parameters

- Argument 1 — Socket: Connection descriptor reported by the playback transport.
- Argument 2 — Video number: Client-assigned video stream number for this playback selection, or its default value when no video is selected.
- Argument 3 — Audio number: Client-assigned audio stream number for this playback selection, or its default value when no audio is selected.
- Argument 4 — Content URI: Configured URI of the advertising media item.
- Argument 5 — Initial video timestamp: Raw video start timestamp value; units follow that timestamp timescale and are not necessarily milliseconds.
- Argument 6 — Initial audio timestamp: Raw audio start timestamp value; units follow that timestamp timescale and are not necessarily milliseconds.
- Argument 7 — Offset: Playback position within the advertisement in milliseconds.

The example uses timestamps with 1,000 ticks per second. The log omits the actual timestamp scales.

## Log examples

Illustrative examples; these are not captured server logs.

```text
s=42, video_sn=1, audio_sn=2 https://media.example/ad.mp4 content start, initial_video_timestamp=120000, initial_audio_timestamp=120000, offset=0
```

## Short description

SLDP aligns audio and video advertising timestamps.

## Trigger condition

A ready audio/video advertising reader is aligned with the stream insertion point while preserving its initial track offset.

## Explanation

Both reader starting timestamps are assigned before requesting the first content item. The printed timestamp values are raw ticks in their associated timestamp scales, which this message does not print.

## Possible causes

- A ready audio/video advertising reader is aligned with the stream insertion point while preserving its initial track offset.

## What to check

1. Check the track timescales and audio/video delay when interpreting these values.

## Recommended action

No action is required for an expected advertising start.
